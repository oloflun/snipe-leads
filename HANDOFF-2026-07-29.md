## 6. The failure and its diagnosis — read this before any design work

The first redesign was verified as: no shadows, no fabricated metrics, correct tokens, zero
horizontal overflow, all tap targets ≥44px. Every claim was true. **None of them measured whether
anything was there.**

Screenshots had failed early (Browser pane not compositing) and instead of solving that, computed-
style checks were substituted. Measured against the page it replaced, using the same probe:

| Metric | Editorial original | The flat redesign | E2 final |
|---|---|---|---|
| Hairline rules | 106 | **2** | 13 |
| Ochre at display scale (≥28px) | 30 | **0** | 11 |
| Mono elements | 134 | 0 | 0 |
| Display type steps | 6 | **1** | 6 |
| Distinct font sizes | 20 | 9 | 15 |
| Images | 1 | 1 | 7 |

Mechanism: seven texture layers were removed and one was added — `paper2` planes sitting 0.035
OKLCH lightness from `paper`, i.e. nearly invisible.

**Deeper cause: the DESIGN.md was written entirely as prohibitions.** No shadows, no borders, accent
under 5%, no mono, no sub-captions. Not one rule said what *creates* visual interest, so a fully
compliant page was necessarily empty. `DESIGN.md` has been rewritten to fix this and now opens with
a section documenting why the previous version failed.

**The rule already existed and still failed.** CARL DESIGN rule 3, added 2026-07-09 after the user
caught the identical failure in `alunix-os`, says: *"Nothing is 'done' without a real screenshot
taken via a live browser preview ... Never claim visual verification without having actually opened
the render."* It failed because it named no fallback when the preview breaks. That hole is what
rules 5–8 below close.

## 7. The four CARL DESIGN rules to add — VERBATIM, NOT YET WRITTEN

Add to the `DESIGN` domain in `C:\Users\Anton L\.carl\carl.json`. Next free id is **5**. Prefer
`mcp__carl-mcp__carl_v2_add_rule` (auto-assigns ids). Do not hand-edit the JSON through Bash to work
around a blocked Edit — that sidesteps the same safety check that is failing.

**Rule 5:**
> Rule 3 has a MANDATORY FALLBACK CHAIN, and computed styles are never a substitute for it. If the
> live browser preview cannot produce a screenshot (pane not compositing, tool unavailable, denied
> navigation), do NOT downgrade to DOM or computed-style assertions — fall back to local capture:
> drive Chromium via Playwright, write PNGs to disk, then READ each PNG with the Read tool so the
> image actually enters context. A screenshot you never opened does not count as having looked. Long
> pages must be captured in viewport-sized slices, because a downscaled full-page image hides the
> detail you are checking for. Reference material is captured the same way and read before the first
> line is written, never recalled from memory.

**Rule 6:**
> Iterate until a full pass finds nothing, not until the output is acceptable. After the first result
> that looks finished, run another complete verification pass (read the render at fold/full/mobile,
> squint test, breakpoint sweep, keyboard, contrast, production perf). Every such pass that finds a
> defect obliges another one. Stop only when a pass comes back clean, and say plainly that it did.
> Continuing past that point is churn; stopping before it ships defects — in the 2026-07-29 Snajp
> run, six real defects were found in passes that came after the page already looked done, including
> a lying html lang attribute and a headline at 2.1:1 contrast.

**Rule 7:**
> When a measurement disagrees with what you can see, suspect the measurement first and prove which
> is wrong. Verifiers fail in both directions. Known traps: sampling a screenshot that still contains
> glyphs measures text-against-text, so hide the text and sample pure background; `scrollWidth`
> cannot see overflow that `overflow-x: clip` is hiding, so test element bounds;
> `img.complete && naturalWidth === 0` misses a lazy image that never loaded at all; dev-mode bundle
> size is meaningless against production. Never report a metric as a pass without knowing what it
> would look like when failing.

**Rule 8:**
> A design system written only as prohibitions produces subtraction. Every rule in a DESIGN.md or
> equivalent that removes something must name what takes its place, and the file must carry an
> explicit section listing what CREATES the design (display type steps, accent at display scale, the
> structural line system, one tonal inversion, a moment that is not information, imagery or a stated
> reason for none). When a redesign brief says "drop X", that changes the idiom, never the amount of
> visual information — confirm the replacement layer before deleting the old one.

**Decision to log** (`carl_v2_log_decision`, domain DESIGN, id will be `design-003`): rationale is
that rule 3 existed and failed for structural reasons; full text is in the draft I attempted, but
the four rule texts above are the load-bearing part. Recall keywords: visual verification,
screenshot fallback, playwright capture, iterate until clean, computed styles not verification,
measurement disagrees, prohibition only design system, design persistence.

### The six defects found *after* the page already looked done

Kept here because they are the evidence for CARL rule 6:

1. Headline broke one-word-per-line: `19ch` is narrower than one long Swedish word at 104px.
2. Divider photograph read cool blue against a warm palette; scrim needed an ochre component.
3. An arbitrary Tailwind class `xl:-ml-[max(0px,calc((100vw-1480px)/2))]` evaluated to 0 at exactly
   1440px, silently killing the grid-break at the commonest desktop width.
4. `.rise` starts at `opacity: 0`, so the page was blank without JavaScript. Fixed with a
   `<noscript>` block in `app/layout.tsx`.
5. `<html lang>` stayed `sv` after switching to English — a screen reader would read English copy
   with Swedish phonetics. Fixed in `lib/i18n.tsx`, applied to all worktrees.
6. The drawn form in E1 was used three times and read as a smudge; hyperborea uses its own once.

### Three false measurements, kept as evidence for CARL rule 7

1. "Overflow at every width" — `scrollWidth === innerWidth`; the forms are deliberately outside and
   clipped. The probe measured geometry, not scroll.
2. "Contrast 1.77:1" — was sampling the ochre glyph and comparing text colour to text colour. With
   text hidden: 8.77:1 for paper text, 4.15:1 for ochre.
3. "Broken images: 0" — the check was `complete && naturalWidth === 0`; a lazy image that never
   loads is not `complete`, so it slipped through.

One that *looked* like an artifact was real: the E1 sun core at `oklch(0.80)` genuinely gave 2.12:1
against paper text. Darkening the form to `oklch(0.54)` was the correct fix; no scrim could rescue it.
