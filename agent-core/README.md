# agent-core/skills — the vendored skill registry

Source data for the DeepSeek-backed support and leads agents
(`snajp-support/app/agentcore/`). Not a Python package — a plain vendored
tree read from disk at runtime. See
[plans/2026-08-07-agent-backend-deepseek.md](../plans/2026-08-07-agent-backend-deepseek.md)
Del D for the full rationale.

**The namespace is not cosmetic.** `mk:customer-research` (research on the
tenant's own customers, run at onboarding) and `cs:customer-research`
(research for a single support ticket, run per case) are different skills
that happen to share a name. An unprefixed skill reference is a bug, not a
convenience — `app/agentcore/registry.py` raises on it (`INV-SKILL-001`).

## manifest.json

Generated by `build_manifest.py`, not hand-edited. `manifest_hash` is the
baseline pack version (plan Del B) — it changes if and only if a vendored
file changes. Re-run after any vendoring change:

```bash
python agent-core/build_manifest.py
```

## Adding or updating a skill

1. Vendor at a specific commit, never a moving branch ref.
2. Record the repo + commit in `SOURCES` in `build_manifest.py`.
3. Re-run `build_manifest.py`.
4. A new `manifest_hash` means a new baseline — it goes through the shadow-eval
   promotion gate (Del B) before any pinned tenant sees it. It never reaches
   one automatically.
